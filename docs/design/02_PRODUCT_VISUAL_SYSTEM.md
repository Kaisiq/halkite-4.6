# Product Visual System

## Core direction

Halkantir should look like a strategic resilience simulator, not a BI dashboard and not a SOC clone.

The visual language should combine:

- operational seriousness
- graph-native intelligence
- polished executive readability

## Look and feel

### Tone

- Precise
- High-stakes
- Analytical
- Premium
- Controlled, not flashy

### Visual metaphor

- Mission control for organizational survival
- Living dependency map
- Scenario war room

## Color system

Use a dark foundation with highly intentional signal colors.

### Base

- Background: deep navy or blue-black
- Surfaces: layered slate and steel-blue panels
- Text: cool off-white
- Secondary text: desaturated blue-gray

### Signals

- Healthy: restrained green
- At risk: amber
- Critical: red-orange
- Active simulation: cyan or mint
- Selected path: electric yellow or ice-blue

### Rule

Color should indicate state, not decoration. The graph and results must remain readable when many nodes are active.

## Typography

Use a more distinctive stack than standard SaaS defaults.

### Recommendation

- Headings: IBM Plex Sans Condensed, Space Grotesk, or Sora
- Body/UI: IBM Plex Sans, Manrope, or Geist
- Numeric panels: tabular numerals where possible

### Rule

Big numbers should feel decision-grade. Headings should feel sharp and technical without becoming sci-fi.

## Layout principles

### Desktop

- Keep the graph as the largest visual object.
- Use secondary side panels for metrics, ranked risks, and scenario details.
- Reserve top-level navigation for the four pipeline steps from the product docs.

### Mobile

- Collapse the graph and results into vertical sections.
- Preserve one high-signal metric at the top.
- Allow scenario cards to become the main interaction object on small screens.

## Motion principles

Motion must communicate computation and causality.

### Good motion

- Tree growth
- Path highlighting
- Cascade propagation
- Ranked-list reshuffling
- New-worst-state reveal

### Bad motion

- Decorative floating elements
- Continuous idle shimmer everywhere
- Overly soft transitions that reduce urgency

## Component style rules

### Cards

- Dense but readable
- Medium radius, not pill-shaped
- Clear hierarchy between title, metric, explanation, and action

### Charts

- Avoid generic rounded dashboard charts where possible
- Prefer line, bar, and heat displays that tie back to network state

### Graph

- Node size should reflect importance
- Node opacity or fill should reflect health
- Failure state should be unmistakable
- Cross-layer relationships should be visibly distinct

## Anti-patterns

- Purple-on-white startup styling
- Empty white dashboards with a graph dropped in the middle
- Overuse of glow effects
- Too many unrelated widgets competing for attention
- Generic KPI tiles with no link back to paths or entities

## Design sentence

Halkantir should look like a live resilience command system that discovers, explains, and ranks catastrophic organizational failure paths.
